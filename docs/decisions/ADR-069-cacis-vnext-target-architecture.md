# ADR-069: CACIS vNext target architecture

Status: `ACCEPTED_BY_OWNER_IMPLEMENTATION_GATED`  
Decision owner: project owner  
Decision date: 2026-07-15  
Review date: after W1 world-model replay or before any new operational authority

## Context and threat-model impact

The owner directed nimrod to incorporate the Constitutional Autonomous Cyber Immune System (CACIS) plan and become a state-of-the-art integrated offense and defense entity. The brief adds a living world model, ephemeral immune organisms, competing hypotheses, adversarial challenge, metacognition, metabolism, homeostasis, Chronos, genome learning, and recursive improvement.

Those capabilities create material risks if agent consensus becomes truth, a scheduler gains execution power, derived state overwrites evidence, an organism verifies itself, reusable memory becomes an instruction-injection path, or recursive evaluation expands authority. The current doctrine already forbids those outcomes.

## Options considered

1. Extend the current fixed swarm and control board without a new architecture boundary.
2. Add a federated constitutional immune plane around the existing kernel, Witness, verifiers, Crucible gates, Foundry, and control-board ingress.
3. Create a separately deployed microservice mesh with a service or process for every organism cell.

## Decision and consequences

Option 2 is accepted as the vNext target architecture. CACIS is subordinate to `DOCTRINE.md` v0.1 and changes no existing authority.

- The Constitutional Kernel remains the only deterministic authorization plane and cannot execute.
- The Sovereign Governor may schedule, meter, pause, and terminate work but cannot authorize an effect.
- Immune organisms are ephemeral, typed, capability-bound, resource-bounded, and proposal-only.
- The World Model is versioned derived state with explicit provenance, contradiction, unknown, and stale states.
- Consequential claims and recovery are independently verified; no organism or candidate self-verifies.
- Genome and recursive improvement remain candidate-only under the existing Foundry, partitioned evaluation, and immutable authority ceilings.
- The Observatory remains a display projection over signed monotonic ingress.
- Operational offensive effects remain exclusively behind existing Crucible authorization, isolated-range, abort, cleanup, recovery, and verification gates.
- New repository packages are created only when a cohesive implementation boundary exists; the logical architecture does not authorize empty scaffolding or duplicate subsystems.

## Privacy, data, and authority changes

This decision creates no collection, credential, target-contact, provisioning, installation, execution, containment, recovery, promotion, distribution, or public-launch authority. Future world-model and genome work must define purpose, retention, minimization, redaction, tenant isolation, deletion, and export before real telemetry is admitted.

## Migration and rollback

Implementation proceeds through the eight waves in `VNEXT_CACIS_MASTER_PLAN.md`, beginning with contract-only deterministic replay. Existing Edge and Crucible contracts remain valid. Rollback removes the vNext roadmap and returns planning to the fixed governed-swarm architecture; it does not weaken doctrine or any existing denial.
