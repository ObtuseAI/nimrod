## Recommendation Summary

The brief is directionally compatible with nimrod, but simply growing the current fixed swarm would concentrate mutable world state, scheduling, hypotheses, and learning in one ownership boundary. A service-per-cell mesh offers stronger isolation but would ask the project to solve distributed identity, ordering, backpressure, deployment, and recovery before its world-model semantics are proven.

I recommend the middle architecture: a federated constitutional immune plane. We retain the current kernel, Witness, verifier, Crucible, Foundry, and signed board boundaries; add an immutable observation ledger and versioned derived world model; make organisms ephemeral and proposal-only; and keep effect execution on the existing path. This creates the conceptual breakthrough without granting a scheduler or learned component new authority.

- Revisit the service mesh only if measured workload, fault containment, or independent deployment ownership makes the additional operational cost proportionate.
